# Internationalisation

Four languages ship: **English, German, French, Polish**. English is the source of truth.

## No literal reaches the screen

```tsx
// ❌
<Button>Save</Button>

// ✅
<Button>{t('common.save')}</Button>
```

This includes `aria-label`, `title`, `placeholder`, toast text, validation messages and
document titles. The only strings that stay literal are domain values that are not translated —
an ISO code, a SKU, a role name like `ADMIN`.

### The one exception

`StartupErrorPage` ships English literals. It is what renders when `bootstrap()`
rejects, and `initI18n()` is one of the two things that may have failed — so
calling `t()` there would either print raw keys or throw a second error on top
of the first. English is the source locale and the honest fallback. Do not
"fix" it by adding keys.

## `en.ts` is typed, the rest conform

```ts
export const en = { /* … */ } as const
export type Translation = typeof en

export const de: Translation = { /* … */ }
```

A missing or misspelled key in `de`/`fr`/`pl` is a **compile error**, not a runtime fallback.
Adding a key to `en` means adding it to all four in the same commit.

## Key naming

`<namespace>.<key>`, namespaces mirroring the feature: `common`, `nav`, `auth`, `theme`,
`language`, `dashboard`, `countries`, `products`, `facilities`, `production`, `users`, `roles`,
`audit`, `errors`, `toast`, `deleteDialog`.

Keys describe **meaning**, not appearance. `common.save`, never `common.greenButton`.

## Plurals

i18next resolves the category through `Intl.PluralRules`. Polish needs `one`, `few`, `many` and
`other`; English and French need two. **Every locale declares all four**, English included, so
the shared `Translation` type covers them.

```ts
facilityCount_one: '{{count}} facility',
facilityCount_few: '{{count}} facilities',
facilityCount_many: '{{count}} facilities',
facilityCount_other: '{{count}} facilities',
```

Call it with `t('dashboard.facilityCount', { count })`.

## Interpolation, never concatenation

```tsx
// ❌ — word order differs by language
<>{t('common.showing')} {from}–{to}</>

// ✅
{t('common.showing', { from, to, total })}
```

## Numbers and dates

Never hand-format. `Intl.NumberFormat` / `Intl.DateTimeFormat` with the active language, via
the helpers in `shared/lib/format.ts`. A German reader expects `1.234,5`; a Polish reader
expects a different date order than an English one.

## The language itself

Held in the URL (`?lang=`) so a shared link keeps the language, with the browser's preference
as the initial default. The `<html lang>` attribute follows it.
